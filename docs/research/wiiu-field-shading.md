#### Terrain mesh transitions and material inputs

The JP v208 program 9 vertex shader samples the current height slice first.
Groups 5–14 then compute `g = max(abs(u − 0.5), abs(v − 0.5))` from the
draw's mesh coordinates and `w = clamp(g·CB12[8].z + CB12[8].w, 0, 1)`.
For `w > 0.01`, it samples a second height slice using the UV transform in
`CB13[9]` and combines the two heights as `lerp(h0, h1, w)` before the world
height scale. `CB12` and `CB13` are `gsys_user1` and `gsys_user2`.

JP v208 RPX `0x036c5b64` reads the effective grid size `N` from the draw
wrapper. `0x036c5b90–0x036c5bd0` computes the two coefficients as
`z = 1/(A/N)` and `w = −(0.5 − A/N − B/N)/(A/N)`. The terrain constructor
at `0x036f2544` and `0x036f2580` initializes `A = 15` and `B = 1.5`.
`0x036c6018–0x036c6070` populates the draw data, which is bound at
`0x036c659c–0x036c65b8`. These are static findings. A matching original
draw still needs to establish its actual `N`, the two slices and transforms,
and how its mesh covers the archive tiles. The independent renderer still
uses skirts on its own tile meshes.

The same program's pixel shader reads the two material IDs from the red and
green of `tera_material` (`t7`, groups 16–23), each as
`floor(255·c + 0.5)`. It fetches both records from buffer `b139` at `ID + 9`.
`tera_normal` (`t8`) supplies the geometric normal components and additional
material weights. `MaterialAlb` and `MaterialCmb` supply the per-material
texture layers at `t9` and `t10`. The independent shader currently shades
each of four `.mate` neighbors before filtering. Reproducing the native
blend first requires recovering the construction of the two bound terrain
textures and checking their channels in an original replay.

### PS 128: Shadows and SSAO – Expand

JP v208 RPX `0x034009f4–0x03400a80` sets `e53.z` to the current shadow
range minus 20 m and `e53.w` to that range minus 40 m. The JP `Main`
graphics configuration defines three cascades and
`depth_shadow_near_0_0` through `depth_shadow_near_0_3` values of 2, 32,
64 and 200 m. These are configuration inputs. The JP v208 main-view
update overwrites the view splits before drawing.

The update at `0x038a616c–0x038a62b0` also writes a set of view splits at
runtime. Below, `state` is the shadow object in register `r29`, and the
offsets are float fields within that object.

```text
first_split = state[0x28] + state[0x70]
far_target = state[0x58]
if (flags & 0x20) != 0 and byte[0x500] == byte[0x501]:
    far_target = clamp(state[0x50c] - state[0x52c] * state[0x530],
                       state[0x58] - state[0x54], state[0x58])
    current_far = lerp(state[0x50], far_target, state[0x534])
else:
    current_far = far_target
second_split = lerp(first_split, far_target, state[0x38])
state[0x50] = current_far
```

The guard at `0x038a5b18–0x038a5b6c` tests bit `0x20` of the halfword at
`state + 0xa`. The bytes are the length and capacity of the view history,
initialized to 0 and 3 at `0x038a5314–0x038a531c`. The reset at
`0x038a5458` clears the length. The update at `0x038a57e8–0x038a58cc`
shifts the saved view records and grows the length up to the capacity.
Filling the history satisfies one of the two guard conditions. The
routine uses the target range for the second split and the current range
for the last split and both environment fade starts.

#### Far shadow weights by time of day

JP v208 `0x0365aa10` reads the effective time angle through
`0x03661b00` and computes `h = (angle / 360) * 24` in hours. The clock
getter normally returns `TimeMgr+0x98` and can select `+0x9c` in a separate
game state. The RGB result is passed to `0x0340a728`, which writes it
to KSys view 0's environment extension at offsets `0x110–0x118`.
[The custom payload starts at UBO offset 0x190](wiiu-water-variants.md#layout-and-ksys-extension),
so these are the RGB lanes of `gsys_environment[42]`.

```python
def far_shadow_weights(h):
    if 5.5 <= h < 19.5:
        center, width = 12.5, 7.0
    elif 19.5 <= h < 22.085 or 2.0 <= h < 3.085:
        return (0.0, 0.0, 1.0)
    elif h >= 22.085 or h < 2.0:
        if h < 2.0:
            h += 24.0
        center, width = 24.042499542236328, 1.9575004577636719
    else:
        return (1.0, 0.0, 0.0)
    red = min(1.0, max(0.0, (center - h) / width))
    blue = min(1.0, max(0.0, (h - center) / width))
    return (red, 1.0 - (red + blue), blue)
```

This describes the curve for effective clock hours in `[0, 24)`. Use
single-precision operations and constants to reproduce the native
arithmetic. The weights are about `(0.357, 0.643, 0)` at 10:00,
`(0, 1, 0)` at 12:30, `(0, 0.5, 0.5)` at 16:00, and
`(0.533, 0.467, 0)` at 23:00. There is an abrupt channel switch at the
22.085 h threshold and another at 3.085 h. A local interpretation of the
PowerPC arithmetic and branches agreed with the single-precision form at
4,120 clock angles, including points around the thresholds. Values bound
by a live Hateno draw are still unmeasured.
